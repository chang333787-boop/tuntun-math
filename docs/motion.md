# 모션 — 어디에 · 어떻게 (조사 팀 R · 11-07)

교사 11-07: "앱 완성도를 위해 필요시에 모션을 어떻게 쓸지도 고민해 봐." · 교사 기준: 모션그래픽은 '정지 그림으로 안 되는 개념 하나에 한 편' · AI 슬롭 X(그라데이션 · 유리 · 빛 번짐 · 바운스 · 네온 X) · 4~6학년 · 크롬북(느린 기기) · 직관성 1순위.
지금 움직임(docs/ui.md 원칙 7): 누름 80ms · 되먹임 등장 160ms · 진행 막대 200ms · 입력 칸 흔들기(빈칸일 때) · 도움 사다리 단계 등장 260ms(hint.js · 작업 중). `prefers-reduced-motion`이면 모두 끔.
근거 번호: 정본 번호([B-R5] …)는 그대로, 새로 찾은 것은 [M-1] …(맨 아래). 도움 사다리 근거는 `hint_ladder.md`의 [H-…].

## 이 앱에 바로 쓸 결론 다섯 줄

1. **움직임이 정지 그림보다 나은 때는 '바뀌는 모습 자체를 배워야 할 때'뿐이다**(바뀜의 특징을 배우면 g = 0.34~0.65, 아니면 g = 0.04 — 차이 없음 [M-3]). 이 앱에서 그것은 **'묶음 바꾸기 — 같은 양인데 모양만 바뀜'** 하나다: 10 만들기 · 받아올림(낱개 10 → 십 막대) · 받아내림(십 막대 → 낱개 10) · 분수 · 소수의 받아내림과 가분수 ↔ 대분수. 이것을 '한 편'으로 만든다.
2. **한 편 = 부품 하나(model.js 그림 위)** · 문제 숫자 그대로 · 2초 안 · 한 번 움직이고 멈춘 채 끝남(되풀이 X) · [다시 보기] 단추 · 세로셈 숫자가 그림과 **같은 때에** 바뀜(11-05 지적 '모형에서 바뀐 것과 식을 잇는다').
3. **도움 사다리에서는 아이가 그 단계를 답한 뒤(또는 답을 본 때) 움직임이 그 답의 뜻을 보여 준다** — 답을 대신 보여 주지 않는다. 배우기 '시범'에서만 먼저 보여 준다. 보기만 하는 움직임은 '안다는 착각'을 만들 수 있다[M-6].
4. **transform · opacity만 · 움직이는 조각 15개 안 · 이징 하나(ease-in-out) · 튐 · 깜빡임 · 빛 X**(깜빡이는 강조는 오히려 해롭다: 이해 g −0.47 [M-9]). 동작 줄이기 설정이면 '전 → 후 정지 그림 + 화살표'(지금 model.js 그림이 그대로 대신).
5. **넣지 말 곳**: 맞음 축하 · 틀림 흔들기 · 카드 등장 · 튼튼이 움직임 · 숫자 굴리기 · 곱셈 배열 · 단위분수 막대 · 수직선 뛰기 · 소수점 맞추기(정지 그림으로 됨). 초등학생 · 수학에서는 '강조 표시'의 효과도 거의 없었다(g 0.19 · 0.08, 의미 없음 [M-9]) — 움직임은 꼭 필요한 한 곳에만.

## 1. 근거

말 풀이: **신호(signaling)** = 봐야 할 곳을 색 · 화살표로 짚어 주기 · **분할(segmenting)** = 긴 설명을 토막으로 나누기 · **학습자 속도(learner pacing)** = 아이가 눌러야 다음 토막으로 · **유혹하는 세부(seductive details)** = 재미있지만 배울 것과 상관없는 그림 · 글 · **일시성(transient)** = 지나가 버려 다시 볼 수 없는 정보.

### 1-1. 애니메이션 대 정지 그림 (강도 상)
- 메타분석 26연구 · 76비교: 애니메이션이 평균 d = 0.37 앞섬. 내용을 '나타내는' 애니메이션이면 0.40, 몸으로 하는 절차(손 기술)를 배우면 1.06. 꾸밈용은 효과가 작다[M-1].
- 더 큰 메타분석 61연구 · 140비교 · 7,036명: 평균 g = 0.226(작음). 글 없이 그림만일 때(0.883) · 말소리를 곁들일 때(0.336) 컸다[M-2].
- 위 자료를 다시 나눠 본 연구: **바뀌는 모습의 특징을 배워야 할 때** 애니메이션이 이겼다(단순한 바뀜 g = 0.340 · 복잡한 바뀜 0.647). 바뀜을 배울 필요가 없으면 차이가 없었다(g = 0.043)[M-3]. → **교사의 '정지 그림으로 안 되는 개념에만'이 바로 이 결과다.**
- 애니메이션이 나아 보인 연구 상당수는 애니메이션 쪽이 내용 · 상호작용이 더 많았다. 좋은 그림은 내용과 꼴이 맞아야 하고(일치 원리), 너무 빠르거나 복잡하면 눈이 따라가지 못한다(파악 원리)[M-4].
- 초보는 '눈에 띄게 움직이는 것'을 보고, 중요하지만 덜 튀는 것을 놓친다[M-5].
- 생각할 일을 애니메이션이 대신해 주면 오히려 배움을 막을 수 있다 — 쉬워 보여 '안다는 착각'[M-6].

### 1-2. 멀티미디어 원리 — 이 앱에 닿는 것 (강도 중~상)
- **학습자 속도 · 분할**: 번개 설명 애니메이션을 아이가 눌러 토막씩 넘기게 하면 전이 문제를 더 잘 풀었다(기억 문제는 같음)[M-7]. 분할 메타 56연구 · 88비교: 기억 · 전이 모두 작음~중간 효과[M-8]. → 도움 사다리의 '한 단계씩 + 단추'가 이미 분할 · 학습자 속도다. 움직임 한 편도 단계 하나에 한 토막.
- **신호**: 103연구 · 12,201명 — 기억 g = 0.53 · 전이 0.33. 그러나 **초등학생(7비교) 0.19 · 0.21, 수학(9비교) 0.08 · −0.03 — 모두 의미 없음.** 그림 속 색 강조는 도움(0.44 · 0.39), **깜빡임은 해로움(−0.56 · −0.47)**[M-9]. → 색으로 짚되 깜빡이지 않는다. 강조 표시에 큰 기대를 걸지 않는다.
- **유혹하는 세부**: 58연구 · 7,500명 넘게 — 꾸밈 세부가 있으면 배운 것이 줄었다[M-10]. → 별 · 폭죽 · 캐릭터 움직임은 '꾸밈 세부'다.
- **시간 근접**: 그림과 설명을 같은 때 · 같은 자리에 — 복잡한 자료일수록 효과가 컸다(50연구)[M-18]. → 모형이 바뀌는 순간 세로셈 숫자도 같이 바뀐다.
- **일시성**: 지나가 버리는 정보는 길고 복잡할수록 손해[M-12]. → 움직임이 끝나면 마지막 모습이 멈춰 남고, [다시 보기]로 언제든 다시.

### 1-3. 아이의 주의 (강도 중)
- 유치원생 24명 · 과학 수업 6번: 꾸밈이 많은 교실에서 딴 데 보는 시간 38.6%(꾸밈 없는 교실 28.4%), 시험 정답 42%(55%)[M-11]. 실험실 교실 연구이고 시간이 지나면 익숙해진다는 재분석도 있다 — 그래도 '화면에 움직이는 꾸밈'을 두지 않을 까닭으로 충분하다.
- 수직선 위 수 다루기(음수 덧셈 · 뺄셈)를 그림 · 말 · 식으로 함께 보여 준 집단은 성적 높은 아이와 어려운 문제에서 더 얻었고, 공간 능력이 높은 아이가 더 얻었다[M-13] → 그림 · 움직임은 어려워하는 아이의 부담을 늘릴 수 있다. 짧고 단순하게.
- 화면 속 조작물(가상 수 모형) 메타: 다른 방법 대비 중간 효과 0.34(후속 논문 인용으로 확인)[M-14] · 밋밋한 모형이 오래 남는다[B-R28] · 십 모형으로 묶음 바꾸기를 먼저 하면 1 · 2학년도 받아올림 · 받아내림을 잘 배운다[B-R5][B-R2].

### 1-4. 동작 줄이기 설정 (기준)
- WCAG 2.1 성공 기준 2.3.3(AAA): 상호작용으로 생기는 움직임은 끌 수 있어야 한다 — 어지럼 · 메스꺼움 · 두통을 겪는 사용자 때문. 권장 기법은 CSS `prefers-reduced-motion`(C39) · 자바스크립트에서도 같은 질의(SCR40)[M-15].
- 기준 2.2.2(A): 저절로 시작해 5초 넘게 움직이는 것은 멈출 수 있어야 한다[M-15] → 우리 한 편은 2초 안이라 해당 없지만, 되풀이(루프)는 하지 않는다.
- 크롬북에서 아이가 이 설정을 직접 켜기 어려울 수 있다(확인 못 함) → 앱 안 선생님 설정에 '움직임 끄기' 하나를 두면 반 전체를 한 번에 끌 수 있다(선택).

### 1-5. 크롬북 성능 (기준)
- 다시 계산(레이아웃) · 다시 칠하기(페인트) 없이 합성만으로 움직일 수 있는 CSS 속성은 지금 `transform`과 `opacity` 둘뿐. 다른 속성을 움직이면 느린 기기에서 끊긴다. 움직일 것만 `will-change: transform`으로 층을 올리고, 층을 마구 늘리지 않는다(층마다 메모리)[M-16].
- 화면 움직임 길이는 대체로 100~500ms, 대부분 100~400ms(400은 큰 화면을 가로지를 때) · 보통 너무 길어서 문제[M-17]. 가르치는 움직임은 이보다 길 수 있으나 **토막 하나는 500ms 안**, 한 편 전체는 2초 안으로.
- 주의(확인 필요): SVG 안 조각의 transform 움직임은 크롬에서 합성만으로 끝나지 않고 SVG를 다시 칠할 수 있다. 그래서 조각 수를 적게(15개 안) · 그림 폭을 작게(지금 model.js 640px 안) 두고, 크롬북에서 실제로 재 본다. 끊기면 조각을 HTML 블록(절대 위치)으로 바꾸는 길이 있다.

## 3. 넣지 말 곳 · 슬롭이 되는 모양

넣지 말 곳(꾸밈만 하는 것 — 유혹하는 세부[M-10] · 눈에 띄는 것만 보게 됨[M-5]):
- 맞혔을 때 별 · 폭죽 · 반짝임 · 튼튼이 점프 · 점수 숫자 굴러 올라가기
- 틀렸을 때 카드 흔들기 · 빨간 번쩍 · 소리(지금 `.shake`는 빈칸 · 숫자 아님 안내에만 쓰고 오답에는 쓰지 않는다 — 그대로 지킬 것)
- 튼튼이의 숨쉬기 · 눈 깜빡임 같은 늘 움직이는 모습(화면 한쪽에서 계속 움직이면 주의를 뺏음[M-11])
- 화면 넘어갈 때 미끄러지기 · 카드가 하나씩 떠오르기 · 목록 순차 등장
- 진행 막대 반짝임 · 단추 맥박 · 로딩 장식
- 같은 움직임 되풀이(루프) · 저절로 다시 재생

슬롭이 되는 모양(교사 기준 · 근거 함께):
- 튀는 이징(스프링 · 바운스 · 넘쳤다 돌아옴) — 수 모형은 '물건'이 아니라 '양'이라 튈 까닭이 없다. 이징은 `cubic-bezier(.4, 0, .2, 1)` 하나.
- 빛 번짐 · 그림자 번짐 · 그라데이션 · 유리 흐림(filter · backdrop-filter) — 슬롭이고, 크롬북에서 다시 칠하기를 부른다[M-16].
- 깜빡이는 강조 — 이해를 떨어뜨렸다(g −0.47)[M-9].
- 크기를 키웠다 줄이는 '두둥' 강조(scale 펄스) — 꾸밈 세부.
- 3D 뒤집기 · 기울기 · 원근.
- 움직임이 끝나도 사라지는 그림(일시성[M-12]) — 끝 모습은 남긴다.
- 영상 · GIF · 로티 파일 — 문제 숫자를 따라 바뀌지 못하고(같은 숫자로 말하기 원칙과 어긋남), 외부 파일 · 무게가 늘고, 세로셈과 같은 때에 맞추지 못한다. 그림은 문제 숫자로 SVG를 그때 만든다(지금 model.js 방식).

## 4. 우선순위 다섯 + 사양

공통 부품(제안): `regroup(svgRoot, plan, { onDone })` — 문제 숫자로 그린 model.js SVG 안에서 조각 묶음(`<g>`)들을 차례로 옮기고(transform) 나타내고 감춤(opacity). 웹 애니메이션 API(`el.animate([...], { duration, easing, fill: 'forwards' })`)로 토막을 이어 붙이고(약속 · Promise), 화면을 떠나면 모두 취소. 끝나면 마지막 모습을 그대로 둠.
- 언제 재생: **배우기 시범** = 그 단계 말풍선이 나올 때 저절로 한 번 / **배우기 함께 · 도움 사다리** = 아이가 그 단계를 맞힌 뒤, 또는 두 번 틀려 답을 보여 줄 때 한 번(답의 뜻을 보여 줌 · 답을 대신 보여 주지 않음 — 결론 3) / 언제든 [다시 보기].
- 사다리와 잇기(hint_ladder.md §2 바꿀 것 1): 단계를 처음 보일 때는 글 + 빈칸만, 한 번 틀리면 모형 그림(정지 · 움직이기 전 모습)을 더하고, 맞히거나 답을 볼 때 움직임 재생.
- 동작 줄이기(`matchMedia('(prefers-reduced-motion: reduce)')` 또는 선생님 '움직임 끄기'): 움직이지 않고 **끝 모습 + 옮겨 간 조각의 처음 자리에 점선 윤곽 + 화살표 + 한 줄 글**(지금 model.js 정지 그림과 같은 꼴). 세로셈 표시는 바로 나타남.
- 성능: 움직이는 것은 `<g>`의 transform · opacity만 · `x/y/width` 속성 · `stroke-dashoffset` · `filter` · `clip-path`는 움직이지 않음 · 움직이는 동안만 `will-change: transform` · 조각 15개 안 · 크롬북에서 성능 패널로 프레임 16ms 안인지 확인[M-16].
- 접근성: 그림의 `aria-label`은 끝 모습으로 바꿔 줌("십 막대 1개를 낱개 10개로 바꿨어요 — 일의 자리 14, 십의 자리 7") · [다시 보기]는 글이 있는 단추 · 소리 없음.
- 자동 시험: e2e에서 `emulateMedia({ reducedMotion: 'reduce' })`로 정지 그림 쪽도 한 장 찍기 · 움직임 뒤 끝 모습의 조각 수 = 문제 숫자인지 검사.

### ① 받아내림 — 십 막대 하나 → 낱개 10개 (예: 84 − 65)
- 무엇이: 왼쪽에 84(십 막대 8 · 낱개 4), 일의 자리 4에서 5를 뺄 수 없음.
- 순서(합 약 1.5초):
  1. 0~150ms: 내줄 십 막대 하나에 청록 테두리가 나타남(opacity) — 짚기 · 깜빡이지 않음.
  2. 150~600ms: 그 막대가 낱개 쪽으로 옮겨 감(translate · 450ms).
  3. 600~850ms: 막대가 같은 자리에서 낱개 10개로 바뀜(막대 opacity 1 → 0 · 같은 자리에 겹쳐 둔 낱개 10개 0 → 1). **같은 때에** 세로셈: 십의 자리 8에 빗금 + 위에 7, 일의 자리 4에 빗금 + 위에 14(지금 colView 표시를 이 순간에 나타냄 · 150ms).
  4. 850~1450ms: 낱개 10개가 원래 낱개 4개 옆 다섯씩 두 줄 자리로 펼쳐짐(각 400ms · 20ms씩 차례).
  5. 끝: 멈춤 · 말풍선 한 줄 "십 막대 1개 = 낱개 10개 → 일의 자리는 14, 십의 자리는 7" · [다시 보기].
- 지금 코드와의 자리: model.js `modelHTML` 뺄셈 쪽(십의 자리 0이면 그리지 않음 — 그대로 · 0이 있는 경우는 보류 항목) · kid.js 시범 · hint.js 단계.
- 동작 줄이기: 끝 모습 + 십 막대가 있던 자리 점선 윤곽 + 곡선 화살표 + 같은 한 줄 글.

### ② 받아올림 — 낱개 10개 → 십 막대 하나 (예: 38 + 45)
- 순서(약 1.5초): 일의 자리 낱개 8 + 5 = 13개가 한데 모임(이미 그려진 상태) → 0~150ms: 그중 10개에 청록 테두리 → 150~600ms: 10개가 세로 한 줄로 모임(차례 20ms) → 600~850ms: 한 줄이 십 막대로 바뀜(겹쳐 둔 막대 opacity 0 → 1 · 낱개 1 → 0) · 같은 때에 세로셈 십의 자리 위 작은 1 · 일의 자리 3 → 850~1300ms: 십 막대가 십의 자리 묶음으로 옮겨 감 → 멈춤.
- ①과 같은 부품을 거꾸로 씀(계획 표만 다름) — 만들기 쉬움.
- 동작 줄이기: 지금 model.js 덧셈 그림(점선 상자 10개 + 화살표 + 십 막대) 그대로.

### ③ 10 만들기 — 10칸 틀 (예: 7 + 8)
- 무엇이: 위 10칸 틀에 점 7개, 아래 틀에 점 8개.
- 순서(약 1.2초): 0~150ms: 위 틀 빈칸 3개에 청록 테두리 → 150~850ms: 아래 틀 점 3개가 하나씩 위 빈칸으로(각 400ms · 150ms씩 차례) → 850~1000ms: 위 틀 옆에 '10'이 나타남(opacity) · 아래에 남은 5 → 멈춤. 식 줄 동시 표시: 7 + 8 = 7 + 3 + 5 = 10 + 5.
- 사다리와 잇기: 단계 1(7 + □ = 10)은 정지 그림(빈칸 3을 아이가 셈) → 단계 2(8을 3과 □로)를 아이가 맞히거나 답을 본 뒤 움직임 → 단계 3(10 + 5).
- 10에서 빼기(13 − 5)는 거꾸로: 13 = 10칸 틀 가득 + 낱개 3 → 틀에서 5개가 빠져나감 → 남은 5와 3.
- 새로 그릴 것: 10칸 틀 SVG(2 × 5 · 점 = 원 · 밋밋하게[B-R28]).
- 동작 줄이기: 옮긴 점 3개를 아래 틀 자리에 점선 원으로 남기고 위 틀에 채운 모습 + 화살표.

### ④ 분수 · 소수 묶음 바꾸기 (예: 3 5/8 − 1 7/8 · 11/7 = 1 4/7 · 0.5 − 0.27)
- 대분수 받아내림: 0~150ms 자연수 막대 하나에 청록 테두리 → 150~400ms 그 막대에 자름 선 7개가 나타남(opacity — 8조각) → 400~800ms 8조각이 5/8 옆으로 옮겨 감 → 같은 때에 식 '3 5/8 = 2 13/8' → 멈춤.
- 가분수 → 대분수: 1/7 조각 11개 중 7개가 모여(translate) 자름 선이 사라짐(opacity 1 → 0) → 막대 1 + 남은 4조각.
- 소수: 0.1 막대 하나가 0.01 칸 10개로(①과 같은 꼴 · 자리 이름만 다름 — engine g4 decCols와 같은 말).
- 같은 부품(조각 묶음 옮김 + 선 나타남/사라짐) · 자연수 ① ②와 같은 모양이라 '자연수 받아내림과 같은 생각'이 이어진다.
- 동작 줄이기: 전 · 후 막대 두 줄 + 화살표.

### ⑤ 단계 신호 — 새 단계 줄과 그 자리 짚기 (hint.js · 배우기 함께)
- 새로 채운 단계 줄만 150~200ms 동안 opacity 0 → 1 · translateY 4px → 0. 지금 단계가 가리키는 세로셈 칸(colView `now`)과 처음 문제의 그 숫자에 옅은 청록 바탕(opacity 150ms · 깜빡임 X).
- 고칠 점(작업 중인 hint.js · app.css): `.hl-steps li:last-child` 등장 움직임이 **다시 그릴 때마다**(같은 단계를 한 번 더 풀 때도) 다시 재생된다 → 새로 추가된 줄에만 `nw` 꼬리표를 붙여 움직이게(진행 칸 `.pseg i.nw`와 같은 방식). 등장 길이 260ms · 8px → 200ms · 4px 안으로(ui.md '되먹임 등장 160ms'와 결을 맞춤).
- 기대치: 초등 · 수학에서 강조 효과는 작았다[M-9] — '어디를 보고 있는지 잃지 않게' 정도로만, 더 꾸미지 않는다.

### 만드는 차례(제안)
1. ①(부품 + 받아내림) → 크롬북 실측 · 동작 줄이기 확인 → 2. ②(계획 표만 거꾸로) → 3. ⑤(작은 고침) → 4. ③(10칸 틀 그림 새로) → 5. ④(분수 막대 그림 새로). ① · ②만으로도 11-05 지적(받아내림 · 받아올림 글이 개념과 안 이어짐)에 바로 답한다.
