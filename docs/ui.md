# 화면 설계 — 2차 '튼튼 공방' (UI-2 · 11-01)

선생님 말(요지): "6학년 애들도 보는 거잖아. 큼직큼직하게 해도 돼. 색감도 연구해 봐. 슬롭 느낌은 안 났으면" · "세로로 긴 버전이네? 주로 쓰는 건 **가로**(크롬북 1366×768)" · "버튼 누를 때 **버튼감**, **상용 서비스** 같은 마감"
1차(UI-1 · 커밋 5bedfd9)는 자리 · 대비 · 누를 곳 크기만 고친 조심스러운 다듬기였음 → 2차는 배치 · 색 체계 · 단추 · 아이콘을 새로 짬.
범위: 보이는 것만(app/css/app.css 새로 씀 · 마크업 · 작은 표시용 코드 · app/js/icons.js 새로). 판정 · 저장 · 흐름 · 서버는 그대로.

## 1. 원칙
1. **가로 먼저** — 넓으면(문제 카드 700px 넘음 · 홈 1100px 넘음) 두 칸, 좁으면(폰) 한 칸. main 최대 폭 1280(선생님 반 화면 1440).
2. **한 화면 = 무대 하나** — 문제 화면(준비 다리 · 다듬기 · 구보 · 점검 · 확인 · 처음 문제 다시 · 고치기 · 거꾸로 찾기)은 카드가 화면을 채움(`min(100vh − 114px, 760px)`). 1366×768에서 스크롤 0.
3. **왼쪽 = 볼 것, 오른쪽 = 할 것** — 왼쪽: 진행 · 문제(크게) · 시범 · 모형 · 단계 · 이야기 글 / 오른쪽 옅은 판: 튼튼이 말 · 짐작 → 보기 → 단추 → 되먹임. 좁으면 한 줄로 쌓되 튼튼이 말이 맨 위(`.qside{display:contents}` + `order`).
4. **납작한 단색 · 중간 채도** — 그라데이션 · 유리 · 빛 번짐 · 번지는 그림자 X. 그림자는 단추 아래 단단한 '턱'(`0 4px 0`) 하나뿐. 구역은 흰 면 + 여백 + 옅은 판(`--panel`)으로만 나눔(카드 속 카드 X — 단계 · 모형 · 묶음 칸은 테두리 없는 옅은 판).
5. **색은 길잡이** — 활동마다 색 하나(아이콘 타일 바탕 · 옅은 바탕 · 왼쪽 띠 · 꼬리표). 같은 활동은 홈 · 탭 · 시작 화면 · 문제 꼬리표에서 같은 색 · 같은 아이콘.
6. **누르는 손맛** — 모든 누를 것(단추 · 할 일 카드 · 타일 · 보기 · 짐작 · 고르는 카드)이 같은 말: 턱이 있으면 누를 수 있음, 누르면 3px 내려가고 턱이 1px로(80ms), 잠기면 납작한 회색(턱 없음).
7. **움직임은 셋만** — 누름 80ms · 되먹임 등장 160ms · 진행 막대 200ms(새로 찬 만큼만). `prefers-reduced-motion`이면 모두 끔.
8. **인쇄는 1차 그대로** — 10분 카드 · 아이 카드 · 한 장 안내 · 가정 안내문 · 아이 자세히(두 칸 · 판 · 턱은 인쇄에서 풀림 · 제목은 시스템 글꼴).

## 3. 글자
- 본문 17px(아이 화면 18px) · 시스템 글꼴(Noto Sans KR · 애플 SD 고딕 · 맑은 고딕).
- 제목 · 탭 · 큰 단추 · 타일 이름 = Jua(한 굵기 · 렌더를 막지 않게 읽음 · 없으면 시스템 글꼴 굵게 · 가짜 굵기 X). 할 일 제목 · 수식 · 문제 글엔 쓰지 않음(숫자 모양이 바뀌면 헷갈림).
- 문제 수식(`#q`) `clamp(34px, 5.4cqi, 56px)` — 1366 · 1920에서 56px · 폰 34px. 시범 문제 48px · 단계 22~30px. 숫자는 `tabular-nums`.

## 4. 단추 · 손맛(상용 마감)
- 주 단추: 주황 바탕 · 흰 글 · 모서리 14px(큰 단추 16) · 높이 52px(아이 56 · 큰 58) · 턱 `0 4px 0 #853712`.
- 보조 단추: 흰 바탕 · 2px 테두리 · 연한 턱. 청록 테두리 단추(다음 갈래)는 청록 턱.
- 누름: `:active` + 터치 · 펜은 `.press`(main.js가 pointerdown에 붙이고 120ms 뒤 뗌 — 크롬 터치에서 :active가 늦거나 안 보임) → `translateY(3px)` + 턱 1px · 80ms. hover는 마우스 기기에서만(`body.touch`면 끔 — 1차 규칙 그대로).
- 상태: 고름 = 청록 테두리 + 옅은 청록 · 맞음 = 초록 테두리 + ✓ · 틀림 = 빨강 + ✕ · 잠김 = 납작한 회색(턱 없음 · 짐작 전 빈칸도 회색). 넘어간 문제는 표시 없음(1차 그대로).
- 오른쪽 판의 주 단추는 판 폭을 채움(자리가 늘 같게). 답한 뒤엔 쓴 단추 줄을 숨기고 되먹임 상자의 '다음'만(`fbSlot` → `.answered`).
- focus-visible: 청록 3px 고리 · 3px 띄움.

## 5. 아이콘(app/js/icons.js) — 24칸 · 선 2 · 둥근 끝 · 글자색을 따름 · 이모지 대신
bridge(준비 다리 · 오늘 탭) · hammer(고치기) · **stairs(다듬기 · 스테이지)** · shoe(구보) · book(이야기 다리) · chart(점검) · back(거꾸로) · star(처음 문제 다시) · search(검산 도구) · clock(시계) · chat(선생님과 같이) · arrow · check.
- 판단을 바꾼 곳: 설계안의 '대패/줄' 대신 **계단** — 다듬기는 정확 → 빠르게 → 오래 세 칸을 오르는 일이라 '스테이지'와 바로 이어지고, 대패는 24px에서 다리미 · 신발로 읽혀(두 번 그려 봄) 아이가 알아보기 어려웠음.

## 7. 하지 않은 것 · 남은 것
- 아이 화면에 오개념 이름 · 순위 · 친구 비교 · 학년 낙인 X(그대로). 선생님 정보는 빼지 않음.
- 새 이모지 X · `:has()` X(모형 · 단계 나란히는 JS가 `with-model` 꼬리표) · 줄 가운데 `//` X.
- **app/js/tools.js · speak.js는 고칠 파일 밖이라 '🔍 ○○으로 확인해 볼까요?' · '🔊 읽어 주기'가 이모지 그대로** — 오래된 이모지라 윈도10에서 깨지진 않음. 바꿀 땐 `icon('search')` · 소리 아이콘 하나를 넣으면 됨(두 줄).
- 문제 카드 넓이 판단은 컨테이너 쿼리(크롬 105 · 사파리 16 이상) — 못 쓰는 브라우저는 한 줄 배치로 보임.
